# 비밀번호 정책 운영 메모

본인 변경(`PATCH /api/auth/password`), 관리자 초기화(`POST /api/users/{id}/password-reset`), 신규 계정 발급은 동일한 비밀번호 정책을 적용한다. 현 비밀번호를 포함한 최근 5개와 사용 종료 후 3개월 이내의 비밀번호를 거절한다. 같은 비밀번호를 현재 사용하는 계정이 100개가 되면 추가 사용을 거절한다. 위반 응답은 HTTP 400 `PASSWORD_POLICY_VIOLATION`이다.

인증 해시는 기존 `PasswordEncoder`로 계정별 솔트를 적용해 저장한다. 전역 통계는 `CHAINWATCH_PASSWORD_PEPPER`를 키로 한 HMAC-SHA256 지문만 저장한다. 이 값은 배포 전 충분히 긴 무작위 비밀로 설정하고, 모든 서버 인스턴스에 동일하게 제공하며, DB와 별도로 보호한다. 운영 중 키를 바꾸면 기존 지문과 새 지문이 달라져 통계가 분리되므로 별도의 재등록 절차 없이 교체해서는 안 된다. `application.yml`의 기본값은 로컬 개발용이다.

기존 DB의 BCrypt 해시에서는 평문 지문을 역산할 수 없다. 기존 계정은 올바른 비밀번호로 로그인할 때 현재 비밀번호를 통계와 이력에 등록한다. 등록 전에는 해당 계정이 전역 100개 사용량에 포함되지 않으며, 과거 비밀번호 이력도 복원할 수 없다. 따라서 기존 계정 전체를 포함한 엄격한 정책이 필요하면 계정별 비밀번호 재발급을 마친 뒤 적용 여부를 판단해야 한다. 재발급이나 본인 변경을 거친 이후의 이력과 통계는 트랜잭션으로 유지된다.

현재 프로젝트는 Hibernate `ddl-auto: update`를 사용한다. 새 테이블과 `user_accounts.current_password_fingerprint` 칼럼은 이에 따라 추가된다. 대량 운영 DB에서는 배포 전에 동일 스키마를 명시적 마이그레이션으로 생성하고, `password_history(user_id, ended_at DESC)` 인덱스와 통계 테이블의 지문 기본키를 확인한다.
